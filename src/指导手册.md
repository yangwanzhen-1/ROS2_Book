# 指导手册

本手册用于说明如何维护、构建和发布这本 ROS 2 学习笔记。

## 项目结构

```text
ROS2_Book/
├── README.md          # GitHub 仓库首页说明
├── .nvmrc             # Node.js 版本（10.24.1）
├── book.json          # GitBook 配置
├── package.json       # GitBook 插件依赖
├── package-lock.json  # 插件的精确版本记录
├── build_book.sh      # 书籍构建脚本
├── plugins/           # 项目自带的本地插件
├── src/               # Markdown 源文件和图片
│   ├── README.md      # 书籍首页
│   ├── SUMMARY.md     # 左侧章节目录
│   └── 各章节目录/
├── docs/              # 构建生成的网页，供 GitHub Pages 发布
└── node_modules/      # 本机安装的依赖，不提交到 Git
```

平时主要编辑 `src/` 中的 Markdown 和图片。`docs/` 由构建脚本自动生成，
不要直接修改其中的 HTML，否则下次构建时会被覆盖。

`_book/` 是 GitBook 的默认输出目录，本项目已经统一使用 `docs/`，因此不再使用
`_book/`。

## 添加或修改章节

可以在章节目录中创建 Markdown 文件，例如：

```text
src/02_生命周期节点/生命周期节点.md
```

文件创建后，还需要在 `src/SUMMARY.md` 中添加对应目录项：

```markdown
- [02 生命周期节点](./02_生命周期节点/生命周期节点.md)
```

只有写入 `SUMMARY.md` 的 Markdown 文件，才会被 GitBook 加入左侧目录并生成网页。

### 自动生成侧边标题目录

如果希望左侧目录自动显示某个页面中的二级、三级和四级标题，只需要在该页面的
`SUMMARY.md` 条目后添加 `<!-- AUTO_TOC -->`：

```markdown
- [02 生命周期节点](./02_生命周期节点/生命周期节点.md) <!-- AUTO_TOC -->
```

运行 `./build_book.sh` 时，`scripts/generate_sidebar_toc.js` 会扫描该 Markdown 文件的
`##`、`###` 和 `####` 标题，并在 `SUMMARY.md` 中自动生成可折叠的多级目录和标题
跳转链接。

脚本生成的内容位于 `AUTO_TOC_START` 和 `AUTO_TOC_END` 标记之间，不需要手动修改。
标题发生变化后重新运行构建脚本，侧边目录会自动同步更新。

多级目录使用缩进表示：

```markdown
- [Navigation2](./03_Navigation2/README.md)
  - [规划器](./03_Navigation2/planner.md)
  - [控制器](./03_Navigation2/controller.md)
```

## 添加图片

建议在每个章节目录中保留自己的 `image/` 文件夹：

```text
src/02_生命周期节点/
├── 生命周期节点.md
└── image/
    └── lifecycle.png
```

在同一目录下的 Markdown 文件中使用相对路径：

```markdown
![生命周期节点](./image/lifecycle.png)
```

这样在 Typora、本地生成的网页和 GitHub Pages 中都能正确显示图片。图片文件也要和
Markdown 一起提交到 Git。

## 构建书籍

在项目根目录执行：

```bash
cd /home/y/docker_ws/aros2_sim/ROS2_Book
./build_book.sh
```

脚本会自动完成以下操作：

```bash
nvm use 10.24.1
gitbook build . docs
touch docs/.nojekyll
```

构建完成后，网页位于：

```text
docs/index.html
```

可以在文件管理器中打开，也可以在浏览器地址栏输入：

```text
file:///home/y/docker_ws/aros2_sim/ROS2_Book/docs/index.html
```

## 启动本地预览服务

需要通过 HTTP 预览时，可以执行：

```bash
cd /home/y/docker_ws/aros2_sim/ROS2_Book
nvm use
gitbook serve
```

然后访问：

```text
http://localhost:4000
```

`gitbook serve` 可能重新生成 `_book/`，它只用于本地预览；正式发布仍然使用
`build_book.sh` 生成的 `docs/`。

## 发布到 GitHub Pages

修改源文件后，按照以下顺序操作：

```bash
cd /home/y/docker_ws/aros2_sim/ROS2_Book

./build_book.sh

git add .
git commit -m "更新书籍内容"
git push
```

其中：

- `build_book.sh` 在本机把 Markdown 构建成 `docs/` 网页。
- `git push` 把源文件和网页上传到 GitHub。
- GitHub Pages 自动发布 `main` 分支中的 `/docs` 目录。

## 在新电脑上恢复环境

`node_modules/` 不会推送到 GitHub。克隆项目后，可以重新安装依赖：

```bash
cd ROS2_Book
nvm use 10.24.1
npm install
./build_book.sh
```

`package.json` 和 `package-lock.json` 会记录需要安装的插件，因此不需要提交
`node_modules/`。

## 常用 Markdown 语法

```markdown
# 一级标题
## 二级标题

普通段落

- 无序列表
- 无序列表

1. 有序列表
2. 有序列表

[链接文字](https://example.com)

![图片说明](./image/example.png)

`行内代码`
```

代码块可以标注语言，以启用语法高亮：

````markdown
```cpp
#include <memory>

#include "nav2_lifecycle_manager/lifecycle_manager.hpp"
#include "rclcpp/rclcpp.hpp"

int main(int argc, char ** argv)
{
  rclcpp::init(argc, argv);
  auto node = std::make_shared<nav2_lifecycle_manager::LifecycleManager>();
  rclcpp::spin(node);
  rclcpp::shutdown();

  return 0;
}
```
````

网页中的多行代码块右上角带有“复制”按钮，点击后会复制代码内容，并短暂显示
“已复制”状态。
